**Status:** active

A wrong numeric premise propagated through gated artifacts took four independent passes to fully purge. In mini-fax feature 002, a false polling-cadence constant (spec asserted 3-5 seconds; the shipped, frozen firmware polls at 10 seconds per POLL_INTERVAL_MS=10000) contaminated the spec narrative, SC-002's latency promise, plan throughput figures, an ADR's Durable Object billing math (~3.3x inflated), two LOGs' write-budget arithmetic, and a contracts file. Two FULL-rigor review panels did arithmetic WITH the wrong number rather than checking it against the source of truth (firmware config.h) — one panel's devil's advocate even computed a "correction" that replaced one wrong figure with another derived from the same false premise. Killing the constant required four passes: (1) a targeted correction pass off the defect record, (2) an independent mining agent that re-derived true figures, (3) a residual grep sweep — which itself missed a case variant ("within 10 seconds" vs "Within 10 seconds", case-sensitive grep) and a synonym surface ("~1 req/sec", the same premise expressed as a rate), and (4) a cross-artifact analyze pass that caught the last survivor inside a user story's independent-test text. Pattern: numeric constants are load-bearing and invisible — review panels verify derivations from premises, not premises themselves. Purging a false constant requires case-insensitive, multi-form sweeps (the raw number, derived rates, prose restatements, unit conversions) plus an explicit premise-vs-source-of-truth cross-check in any analyze/consistency step. Also argues for making cross-artifact analyze a mandatory step rather than optional in spec-driven workflows — the same lesson as PHI-027, one level down.
