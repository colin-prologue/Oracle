## PHI-030 — Verification before autonomy

**Date:** 2026-06-11
**Revision:** 2026-07-06 — consolidation pass 1: absorbed PHI-013 (disk as truth), PHI-038 (reuse existing independence), PHI-041 (evidence before self-report) as named corollaries
**Domain:** architecture
**Source Project:** AgentChat (agent-team); corollaries from Claude-Root and Switchboard
**Source:** Guiding-principles interview chose a developer agent as the next role (pure throughput); the immediate counter-finding was that a dev teammate without a QA/review leg makes the owner the full-time reviewer. Written into the agent-team constitution as "the ordering constraint" so it survives enthusiasm.

### Philosophy
No agent executes autonomously on a task type until independent verification — something other than the owner — exists for that task type. Granting execution autonomy without a verification leg doesn't remove the human bottleneck; it relocates it downstream, converting the owner from executor into full-time reviewer. Verification can be another agent, an automated gate, or a test harness — but its existence is the precondition for moving any autonomy ratchet past draft-mode, and the constraint should be written where enthusiasm can't erode it. Independence means independent from the author: verification that reuses the author's model of the world, the author's fixtures, or the author's self-account inherits the author's blind spots and certifies the misconception rather than the behavior.

### Corollaries
- **Disk as truth, not worker summaries (ex-PHI-013, merged 2026-07-06):** a coordinator that parses returned worker summaries as audit truth has no independent observation surface — lying, hallucinating, or omitting summaries are an unfixable failure class, and the audit trail becomes a fiction generated by the actor it is supposed to audit. Prefer architectures where workers write directly to a shared on-disk artifact during execution and the coordinator reads disk for routing decisions, never trusting a returned string as source of truth. Boundaries: parallel writes need a protocol (single-writer-per-stage, append-only with worker ID prefix); some signals (e.g., model confidence) aren't artifact-shaped; summary-trust is fine for deterministic, fully-tested workers or when an independent channel (filesystem events, telemetry) catches lying summaries.
- **Reuse existing independence (ex-PHI-038, merged 2026-07-06):** when a requirement calls for independence — a fresh-context reviewer, a different-model verifier, an isolated judge — first check whether a component already in the pipeline satisfies it, and fold the new concern into that step rather than spawning a second dedicated one. The discriminating test: "independent from the author, or merely independent from another reviewer?" Only the former is what such requirements demand; a second independent check of the same artifact at the same point is usually over-design. Boundaries: if the existing component's independence is incidental rather than guaranteed by construction, it can't be relied on and a dedicated step is justified; if folding dilutes the primary check's attention (missed defects), a dedicated second reviewer earns its cost; mitigate mixed concerns by ordering (primary verdict first) rather than splitting.
- **Evidence before self-report (ex-PHI-041, merged 2026-07-06):** when a fresh reviewer dissects another actor's failure, sequence the evidence — mechanics first, self-report last, disagreements surfaced, reporting both verdicts when they differ. Reading the self-report first buys anchored agreement, not independence: you pay for a fresh perspective and receive the rut's self-justification with a second signature. The self-report informs; mechanical signals decide ties. Boundaries: for mechanically unambiguous failures the ordering is moot; the extreme form (never read self-reports) discards genuinely useful pointers.

### Why I Hold This
Multi-agent failure research (UC Berkeley MAST taxonomy) attributes a large share of failures to verification gaps, and "tester approves without testing" is a recognized failure mode. In agent-team's design session, the pull toward shipping a developer role first was strong precisely because throughput is the visible win — the review burden it creates is invisible until it arrives. The corollaries are the same independence requirement at three surfaces: the coordinator's observation channel (spec-010 review — an audit trail synthesized from worker summaries has no way to catch a worker that returns "looks fine" having skipped the work), the verification pipeline's structure (Plan 3-C leanness review collapsed a proposed tier-judge into the existing verifier, already model≠author by construction — get the independence you need, but get it once), and the reviewer's read order (issue #10's failure class was diagnosed correctly from transcript mechanics alone, no worker testimony needed).

### Evidence
- OBS-023 — test doubles inherit their author's blind spots: 110 tests green around a BLOCKER-severity defect; closed only by a verifier with independent knowledge of the real system (supports)
- OBS-026 — author-written gates blind to a lockstep ownership exploit; an independent bot review caught within minutes what 44 author-written tests missed — same shape, third domain (supports)
- OBS-024 — permission-wall diagnosis derived from transcript mechanics alone; worker self-context unnecessary and potentially misleading (supports, ex-PHI-041 grounding)
- Switchboard Plan 3-C escalation review, 2026-06-24 — redundant tier-judge deleted with no loss of required independence (supports, ex-PHI-038 grounding)
- UC Berkeley MAST taxonomy — verification gaps as a leading multi-agent failure share

### Where It Applies
Any system delegating execution to agents or automation: agent teams, CI auto-merge policies, autonomous workflow runners, scheduled jobs that mutate state, distributed task runners routing on worker-reported status, post-mortem and incident review over self-described work, code review of self-described PRs, LLM-judge pipelines. Kicks in whenever an autonomy level is about to increase — the question is "what, other than me or the author, checks this?" before "what can it do?"

### Known Tensions
- Verification roles produce no visible output of their own, so they lose prioritization fights against capability roles unless the constraint is pre-committed in writing.
- For low-stakes, easily-reversible task types, mandatory independent verification is over-engineering; the constraint is about autonomous execution, not drafts or proposals.
- Disk-artifact protocols cost latency, write-contention handling, and schema rigidity relative to trusting returned values.
- Evidence-first review is slower than summary-first; it earns its overhead only where interpretation matters.

### Open to Revision When
- Owner-review at a gate (e.g., AgDR verdicts) proves to scale sustainably for some task types, making independent verification unnecessary there.
- A task type proves so reliably reversible that post-hoc audit beats pre-merge verification on total cost.
- Evidence-first reviewers empirically converge with summary-first reviewers at materially lower cost, or self-reports become schema-constrained to facts-only.
- Folding concerns into one verifier repeatedly degrades the primary check — attention dilution showing up as missed defects.
